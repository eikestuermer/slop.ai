# Schema

Slop AI uses three JSON Schemas as the single source of truth for the data
that flows between Rust, TypeScript, and the planner LLM.

## Files

All schemas live in [`packages/schemas/`](../packages/schemas/) at draft 2020-12.

- `timeline.v1.json` - app-state. The canonical project document.
- `ops.v1.json` - reversible commands written to `ops.jsonl`.
- `plan.v1.json` - strict contract for planner LLM responses.

## Code generation

- **Rust**: typed Rust mirrors live in [`crates/slop-core/src/timeline.rs`](../crates/slop-core/src/timeline.rs),
  [`ops.rs`](../crates/slop-core/src/ops.rs), and
  [`plan.rs`](../crates/slop-core/src/plan.rs). For V1 these are kept in
  sync by hand. The schema text is loaded via `include_str!` at compile
  time and validated at runtime by `slop_core::validator`. A future build
  step will codegen with `schemars` + `typify`.
- **TypeScript**: types are auto-generated by
  `pnpm --filter @slop/schemas codegen` into `packages/schemas/generated/`.
  The frontend imports from `@slop/schemas`.

## Versioning

Major version bumps (`*.v2.json`) are reserved for breaking changes:

- removing a property,
- changing a property type,
- changing the meaning of an existing property.

Each breaking change requires a migration in
`crates/slop-core/src/migrations/` that converts a `*.v1.json` document
into a `*.v2.json` document. The migration is exercised by tests on the
fixture projects in `examples/sample-projects/`.

Additive changes (new optional properties, new enum values that the schema
already declares as open) are made in place and are not breaking.

## Why JSON Schema, not protobuf or just Rust types?

Because the schema needs to live in three places:

1. As a runtime validator on the Rust side.
2. As TypeScript types on the frontend.
3. As a structured-output constraint for the planner LLM.

JSON Schema is the only format that is natively supported by all three.
Modern LLM APIs (OpenAI, Ollama, llama.cpp server) all accept a JSON Schema
as the response-format constraint, which means the same document we use to
validate also constrains generation.
